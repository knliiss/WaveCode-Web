<h1 align="center">WaveCode Web</h1>

<p align="center"><strong>Media, in a mark.</strong><br>Scan and create WaveCodes, opening content on the original platforms.</p>

<p align="center">
  <a href="https://github.com/knliiss/WaveCode">Rust SDK & format</a> ·
  <a href="https://github.com/knliiss/WaveCode-Web/actions">Build status</a>
</p>

A **mobile-first** optical scanner and media-link generator for the open-source
[WaveCode](https://github.com/knliiss/WaveCode) V1 format. White and black, capsule-shaped
geometry, a continuous quiet channel and a deliberately restrained interface
built for one-handed use on a phone.

This is a standalone **frontend**, not a decoding service. Images never leave
the device. Encoding and scanning are performed by the **official WaveCode
Rust code compiled to WebAssembly**, in a Web Worker.

## Features

- **Live camera scanning:** rear camera preferred; multiple crop/scale strategies,
  adaptive scan cadence, orientation handling via the official decoder, and
  torch/rear-camera switching where available.
- **Photo scanning:** mobile photo upload, progressive high-detail passes, overlapping tile search for tiny codes,
  code candidates presented individually when several are found.
- **Code creation:** support for seven music services plus YouTube videos, Shorts, TikTok and Instagram Reels. Native timestamps are offered only when supported; every code remains 36 columns.
- **Export:** actual SVG or PNG generated by the Rust renderer.
- **On-device privacy:** camera video and uploaded images remain local; no account,
  telemetry SDK or track lookup server.
- **Responsive UI:** mobile-first, safe-area aware, accessible labels and controls,
  reduced-motion support, clear camera permission and failure states.

## Architecture

The app intentionally keeps the codec **outside** frontend code.

    src/
      domain/                  Media URL validation, V1 contracts, native timestamps
      infrastructure/
        wavecode/              Web Worker RPC and WASM adapter
        camera/                Video/photo capture and image-scaling policy
        download.ts            Local client-side file downloads
      features/
        scanner/               Camera lifecycle, scan state, result presentation
        create/                Encode URL, preview, export, share actions
      app/                      Shell, primary navigation, brand
      styles.css               Responsive design system
      generated/wavecode/      Locally built WASM artifact (gitignored)
    scripts/build-wavecode.sh   Reproducible build from pinned upstream commit
    tests/                      Pure domain and capture policy tests

The frontend never implements the Reed–Solomon codec, CRC, V1 frame layout or
optical algorithm. A single WASM worker owns the Rust SDK and communicates with
the UI using small typed requests. Heavy decoding work never runs on the UI
thread.

## Local setup

Requirements: Node.js 22+, npm, Git, Rust with the
\`wasm32-unknown-unknown\` target and \`wasm-pack\`.

\`\`\`bash
git clone https://github.com/knliiss/WaveCode-Web.git
cd WaveCode-Web

rustup target add wasm32-unknown-unknown
cargo install wasm-pack --locked

npm install
npm run sdk:build
npm run dev
\`\`\`

For end-to-end tests, install Chromium with `npx playwright install chromium`, then run `npm run build && npm run test:e2e`.

The UI is served by Vite. **Live camera access requires HTTPS or localhost**;
a phone visiting a private HTTP LAN address may not be permitted to use its
camera. File scanning and creation can still work when camera access is unavailable.

The WASM build script clones the [WaveCode](https://github.com/knliiss/WaveCode)
source into \`.cache/wavecode\`, checks out the pinned commit, builds the official
WASM adapter and writes generated bindings to \`src/generated/wavecode\`.
Generated outputs are ignored by Git to avoid accidentally committing stale
compiled codecs. If you update the SDK pin, rerun \`npm run sdk:build\` and the
complete tests before committing.

## Deployment

The built frontend consists entirely of static files: deploy \`dist/\` to
Cloudflare Pages, Netlify, Vercel static hosting or any HTTPS server.

When building directly from Git in a hosted environment, **install Rust +
wasm-pack and run \`npm run sdk:build\` before \`npm run build\`**. GitHub Actions
does exactly this and uploads a ready-to-deploy \`dist\` artifact.

No backend, API keys, CORS proxy or persistent database are needed.

### Security and limitations

- Decoded links are only opened when they use HTTPS and an explicitly supported
  media-platform hostname. Unknown URLs never become clickable results.
- No media metadata, creator handles or recordings are embedded in the codes.
  Scans open original-platform URLs, never a WaveCode-hosted player. Timed
  Shorts use the regular YouTube watch URL.
- TikTok and Instagram Reels do not accept timestamps without a supported
  native seek link. TikTok uses its ID-only `/@/video/<id>` route, which may vary
  by TikTok client. Short `vt.tiktok.com/<share-code>/` links are encoded directly
  and losslessly without resolving the redirect. Short links may expire or be
  unavailable later, and the short form is a distinct WaveCode identity.
  Other short-link hosts (including `vm.tiktok.com`) still require expansion.
- Camera exposure, blur, bar damage, deep perspective, and reflections can
  reduce optical success. The decoder uses error correction, but no optical
  recognition algorithm guarantees every real-world photo.
- Camera/torch APIs vary across browsers and devices. A good photo upload
  path is always available.
- Some browsers require a user interaction before granting camera access.
- WebAssembly is compiled into the site's static assets. Building the SDK is
  not the same as calling an external decoding API.
